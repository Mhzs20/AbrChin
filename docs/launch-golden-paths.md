# مسیرهای طلایی لانچ ابرچین

این سند معیار پایان لوپ نجات محصول است. هر تغییر لانچ باید هر پنج مسیر را بدون
دورزدن گیت‌های مالی، عملیاتی و امنیتی حفظ کند.

## ۱. خرید مستقیم سرور

1. مشتری فقط SKU منتشرشده، دارای قیمت معتبر و حداقل یک سیستم‌عامل قابل انتخاب را می‌بیند.
2. پس از ورود، سیستم‌عامل، نام سرور، دوره ۱/۳/۶/۱۲ ماهه و کد تخفیف را انتخاب می‌کند.
3. Quote به مدت ۶۰ دقیقه قیمت نهایی، مالیات، تخفیف و نسخه پرچین را قفل می‌کند.
4. پرداخت موفق فقط سفارش را وارد صف تأیید ساخت می‌کند و مستقیماً Provision نمی‌کند.
5. Admin تأیید اول را ثبت، سرور را دستی آماده و نتیجه سلامت را ثبت می‌کند.
6. Admin تأیید دوم را ثبت و اطلاعات دسترسی یک‌بارمصرف به مالک تحویل می‌شود.

معیار قبولی: Retry هیچ پرداخت، سفارش، ساخت یا تحویل تکراری ایجاد نمی‌کند و نام Provider
در هیچ صفحه مشتری نمایش داده نمی‌شود.

## ۲. پیشنهاد قطب‌نما تا خرید

1. نیاز مشتری در یک گفت‌وگوی پیوسته و بدون شمارنده سؤال یا نوار پیشرفت دریافت می‌شود.
2. برداشت نیاز پیش از پیشنهاد قابل تأیید یا اصلاح است.
3. فقط پیشنهادهای واقعاً قابل‌خرید همراه دلیل، سطح پرچین و ظرفیت معتبر نمایش داده می‌شوند.
4. تنظیمات تحویل و Quote همان قرارداد خرید مستقیم را استفاده می‌کنند.
5. پرداخت و تحویل دقیقاً از دو گیت Admin مسیر اول عبور می‌کند.

معیار قبولی: Resume از وضعیت Server-side ادامه می‌دهد؛ Draft محلی حق عبور از گیت جریان را ندارد.

## ۳. عملیات Admin: پرداخت تا تحویل

1. هر سفارش در یکی از صف‌های «تأیید»، «ساخت»، «تحویل»، «نیازمند رسیدگی» یا «تمام‌شده» است.
2. کارت سفارش اقدام بعدی، مبلغ فروش، هزینه تأمین، منطقه و دلیل توقف را روشن نشان می‌دهد.
3. جزئیات فنی پشت بخش بازشونده است و مانع تصمیم روزمره نمی‌شود.
4. تأیید ساخت و تأیید تحویل دو Action مستقل با Audit actor/time/reason هستند.
5. خطای سلامت یا تحویل به صف رسیدگی می‌رود و با Retry idempotent بازیابی می‌شود.

معیار قبولی: هیچ مسیر UI یا API با صرف «پرداخت موفق» سرور فعال یا Secret را قابل مشاهده نمی‌کند.

## ۴. چرخه عمر مشتری

1. «سرورهای من» وضعیت واقعی، اقدام بعدی، IP، سیستم‌عامل و محل را نمایش می‌دهد.
2. سرویس در حال ساخت به مشتری می‌گوید اقدام با ابرچین است؛ تایم‌لاین نمونه‌ای وجود ندارد.
3. سرویس فعال دسترسی امن، تمدید، تغییر منابع، لغو و درخواست پشتیبانی دارد.
4. هر سفارش Snapshot منابع، دوره، تخفیف و قرارداد پرچین زمان خرید را نگه می‌دارد.
5. لغو، Refund یا Upgrade فقط مطابق قوانین کیف پول و Ledger ثبت می‌شود.

معیار قبولی: کاربر فقط منابع متعلق به خودش را می‌بیند و Secret فقط برای مالک و فقط طبق سیاست Reveal است.

## ۵. آمادگی فروش و کنترل مالی

1. Arvan تنها منبع Admin است؛ قیمت مشتری از SKU منتشرشده می‌آید.
2. SKU بدون Image، قیمت معتبر یا وضعیت Purchasable در فروشگاه ظاهر نمی‌شود.
3. پرچین شروع/استوار/کهکشان نسخه‌دار و قابل Snapshot است؛ تغییر آینده سفارش قبلی را عوض نمی‌کند.
4. تخفیف دوره، Coupon، VAT، هزینه تأمین و حاشیه سود با Integer Rial محاسبه می‌شوند.
5. Secret scan، migration safety، lint، typecheck، build و تست‌های دامنه پیش از انتشار سبز هستند.

معیار قبولی: Dashboard ادمین یا «اقدام منتظر» را نشان می‌دهد یا دلیل دقیق آماده‌نبودن فروش را.

## تعریف آماده دیپلوی

- هر پنج مسیر بالا پوشش رفتاری یا تست قرارداد دارند.
- Migrationها additive، تکرارپذیر و بدون بازنویسی تاریخچه مالی/سفارش‌اند.
- Build production، lint، typecheck، secret scan و مجموعه تست لانچ سبز است.
- متغیرهای محیطی و چک‌لیست عملیاتی `docs/production-deployment.md` در مقصد آماده‌اند.
- اجرای Deploy و Migration روی سرور همچنان یک عملیات جدا و نیازمند دستور صریح Founder است.
